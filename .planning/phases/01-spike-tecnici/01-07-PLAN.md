## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| file ostile → processo figlio | input non fidato interpretato da PDFium, lopdf, zip |
| figlio → padre | solo una riga JSON limitata su stdout; nessuna memoria condivisa |
| container worker → host/rete | nessuna rete, filesystem read-only, utente non root |

| Threat ID | Category | Severity | Component | Disposition | Mitigation Plan |
|-----------|----------|----------|-----------|-------------|-----------------|
| T-01-07-01 | Elevation of privilege | high | PDFium/lopdf nel figlio | mitigate | processo per documento con rlimit AS/CPU/FSIZE/NOFILE/CORE, container `network_mode: none`, `read_only`, `cap_drop: [ALL]`, `no-new-privileges`, utente 10001 (D-08, T-09); misurato in `hostile.csv` |
| T-01-07-02 | Denial of service | high | decompression bomb PDF/DOCX, 10k pagine | mitigate | prescan in streaming con tetti e `take`, limite pagine 2.000, timeout di parete + `killpg`, cgroup del container come rete di sicurezza (T-07) |
| T-01-07-03 | Tampering | high | PDF attivi (JS, Launch, EmbeddedFile, object stream) | mitigate | quarantena con motivi, incluso il caso nascosto in object stream (D-05, T-10) |
| T-01-07-04 | Tampering | high | supply chain PDFium e tessdata | mitigate | download HTTPS con `sha256sum -c` su hash fissati nel Dockerfile; versione registrata in `hw.json` (T-28) |
