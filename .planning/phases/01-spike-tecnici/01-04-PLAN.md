Poi il codice, in `spikes/s01-upload/` (solo dentro la propria cartella e `spikes/docker/garage.toml`):
- `lib.rs` espone i moduli `upload`, `validate`, `sink`; `main.rs` avvia il server su `0.0.0.0:8080` dentro il runner con `--adapter garage|pgbytea|null`.
- `upload.rs`: handler `POST /upload` come RESEARCH §3: `Multipart` con `field.chunk()` (mai `field.bytes()`), un solo campo `file`, tempfile con `tempfile::NamedTempFile::new_in("/work/tmp")` (volume Linux, D-03), sha256 in streaming, contatore manuale `MAX_FILE = 26_214_400`; `DefaultBodyLimit::max(MAX_FILE + 64 KiB)` sulla sola route e `RequestBodyLimitLayer::new(MAX_FILE + 64 KiB)` globale (tre livelli, D-04). Ordine: stream su tempfile → `validate::check(path, head)` eseguito dentro `tokio::task::spawn_blocking` (lettura zip e scansione a byte del PDF fino a 25 MiB sono lavoro CPU-bound e I/O sincrono: mai sul runtime async) → `sink.put(sha, path)` → transazione breve su Postgres con riga `upload` + riga `outbox` (`event_id` UUID univoco) → risposta. Nessuna chiamata esterna dentro la transazione. Risposta JSON sempre `{upload_id, sha256, size_bytes, status}` con `upload_id` nuovo per richiesta e `status` ∈ `accepted|quarantined`: nessun campo o codice che riveli se il contenuto esisteva già (D-02, T-11). Il nome file del client non entra né nella chiave né nel percorso (T-08). Il server misura con `common::timer::Stopwatch` le fasi receive+hash, validate, persist_original, tx_outbox e le scrive in un CSV per richiesta solo in modalità bench.
- `validate.rs`: magic bytes (`%PDF-` per PDF; `PK\x03\x04` + `[Content_Types].xml` + `word/document.xml` per DOCX; UTF-8 valido senza byte NUL per Markdown); DOCX con crate `zip`: ≤ 1.000 voci, somma dei `size()` dichiarati ≤ 200 MiB, rapporto di compressione per voce ≤ 100 oltre 16 MiB, lettura in streaming con `take()` per non fidarsi del dichiarato, rifiuto di `vbaProject.bin` e del tipo `.docm`, rifiuto di `<!DOCTYPE` o `<!ENTITY` nelle parti XML (XML bomb, T-07); PDF: scansione a byte del file (con decodifica degli escape `#hh` nei nomi) per `/Encrypt` nel trailer → rifiuto, e per `/JavaScript`, `/JS`, `/Launch`, `/EmbeddedFile` → `quarantined`. Dichiarare in un commento di testa che è un prefiltro economico: oggetti dentro object stream compressi sfuggono, e il controllo autorevole sta nel processo isolato di S-02 (D-08).
- `sink.rs`: trait locale allo spike `BlobSink` con `async fn put(&self, key: &str, path: &Path) -> anyhow::Result<()>` e `async fn get_range(&self, key: &str, range: Range<u64>) -> anyhow::Result<Bytes>`; `GarageSink` con `object_store::aws::AmazonS3Builder` (endpoint, credenziali e bucket solo da env, `with_allow_http(true)` motivato dalla rete compose locale, regione `garage`, path style di default, `object_store::buffered::BufWriter` + `shutdown`), chiave `sha256/<hex>`; `PgByteaSink` con tabella `blob_chunk` di RESEARCH §3 (chunk da 1 MiB, `STORAGE EXTERNAL`, una transazione per oggetto, `ON CONFLICT DO NOTHING` per idempotenza); `NullSink` (solo streaming + hash). Il trait resta dentro lo spike: le firme di prodotto le scrive S-07 (WIRING W16).
- `sql/schema.sql`: tabelle `upload(id uuid pk, sha256 text not null, size_bytes bigint, status text, created_at timestamptz)`, `outbox(event_id uuid unique not null, payload jsonb, created_at timestamptz)`, `blob_chunk` come sopra.
- `src/bin/probe.rs`: sottocomandi `gc` (crea oggetti orfani, misura list+head e la cancellazione di quelli più vecchi di N ore con N parametrico, CSV `gc.csv`), `range` (p95 di letture da 64 KiB per adapter, CSV `storage.csv`), `pgsize` (WAL e dimensione tabella).
