## Assegnazione dei pattern

### `spikes/tools/session.sh`, funzione `dc()`

**Analogo:** `spikes/s01-upload/bench.sh`, righe 381-388 (commit `9341b43`)

```bash
  # Nell'interpolazione di compose l'ambiente della shell vince su --env-file: una
  # variabile omonima dell'host (es. DATABASE_URL di un altro progetto) arriverebbe al
  # runner al posto del valore degli spike. Si tolgono dall'ambiente le chiavi del file
  # segreti; si stampano solo i nomi.
  local k
  for k in $(grep -oE '^[A-Za-z_][A-Za-z0-9_]*' "$CKA_SPIKES_ENV" | sort -u); do
    if [[ -n ${!k+x} ]]; then echo "bench.sh: tolta dall'ambiente host la variabile $k (vale il file segreti)"; unset "$k"; fi
  done
```

Da riprendere: il commento che spiega il perché, la lettura dei soli nomi con `grep -o` (mai i valori), il test `${!k+x}` per sapere se la variabile è presente nell'host, la stampa del solo nome.

Da **non** copiare così com'è:

- **Il regex di bench.sh non gestisce il prefisso `export`.** Su una riga `export FOO=...` cattura la parola `export` e non `FOO`. Va usato lo stesso schema che `check_env` già accetta (`session.sh:71`):
  ```bash
  grep -qE '^[[:space:]]*(export[[:space:]]+)?COMPOSE_PROFILES[[:space:]]*=' "$CKA_SPIKES_ENV"
  ```
  Generalizzato per estrarre il nome, per esempio con
  `sed -nE 's/^[[:space:]]*(export[[:space:]]+)?([A-Za-z_][A-Za-z0-9_]*)[[:space:]]*=.*/\2/p'`
  (così si saltano i commenti `#` e le righe vuote, e il valore dopo `=` viene scartato senza essere stampato né salvato).
- **`unset` nella shell di bench.sh** modifica l'ambiente di tutto lo script. In `session.sh` la D-01 chiede di togliere le chiavi solo dal processo compose: si costruisce una lista `-u K` e si lancia `env -u K1 -u K2 … CKA_RUN_ID="$rid" docker compose …`. In questo modo `session.sh` resta senza stato e `cmd_with` (che esporta `CKA_RUN_ID` alla riga 448 e lancia il comando dell'utente alla riga 463) non cambia comportamento.
- **`CKA_RUN_ID` va esclusa dalla lista** anche se un giorno comparisse nel file segreti, perché la imposta `dc()` stesso (D-01). Anche `COMPOSE_PROFILES` è già esclusa a monte: `check_env` si ferma se è nel file (riga 71) e la riga 33 la toglie con `unset`.
- **Messaggio:** se si stampa qualcosa, va su stderr tramite `err` (`session.sh:43`), perché alcune uscite di `dc` vengono lette da programmi: `all_services` (riga 86) legge `config --services`, `cmd_up` (righe 286-288) legge `config --format json`. Una riga su stdout romperebbe quelle letture.

**Punto d'innesto:** tutte le chiamate a compose passano da `dc()` (righe 86, 286, 306, 330, 341, 349), quindi basta correggere lì. `check_env` va chiamato prima di leggere le chiavi, come succede già alla riga 79.

**Forma attesa di `dc()`** (bozza per il planner, non è codice da incollare):

```bash
# Nomi delle chiavi del file segreti, mai i valori (accetta il prefisso export).
secret_keys() {
  sed -nE 's/^[[:space:]]*(export[[:space:]]+)?([A-Za-z_][A-Za-z0-9_]*)[[:space:]]*=.*/\2/p' \
    "$CKA_SPIKES_ENV" | tr -d '\r' | sort -u
}

dc() {
  local rid=$1; shift
  check_env
  local unset_args=() k
  while read -r k; do
    [[ -n $k && $k != CKA_RUN_ID ]] || continue
    unset_args+=(-u "$k")
  done < <(secret_keys)
  env "${unset_args[@]}" CKA_RUN_ID="$rid" docker compose --env-file "$(hostpath "$CKA_SPIKES_ENV")" \
    -f "$(compose_file)" "$@"
}
```

Il `tr -d '\r'` segue l'uso già presente alla riga 288: il file segreti può avere fine riga CRLF su Windows.

**Perché `compose.yaml` non cambia (D-03):** il runner riceve i segreti tramite interpolazione `${VAR}` nella sezione `environment:` (`spikes/compose.yaml:222-230`, per esempio `DATABASE_URL: ${DATABASE_URL}`, `POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}`), non tramite `env_file:`. Il difetto sta quindi solo nella precedenza dell'interpolazione, e togliere la chiave dall'ambiente del processo compose basta a farla risolvere dal `--env-file`. Lo stesso vale per `postgres` (righe 38-40) e `garage` (righe 59-63). Va aggiornato anche il commento d'intestazione di `session.sh` alle righe 25-26 («compose legge il file segreti con --env-file») con la nuova garanzia.

Convenzioni: intestazione con scopo, data UTC e `git_rev` di base; ogni comando con il prefisso `$ `, poi l'uscita, poi `[exit N]`; una sezione `## Prova x` per ciascun punto di D-02, chiusa da una riga `esito x: … (atteso …)`; una sezione `## Pulizia` finale con `down`, `release`, `status` ed elenco dei container rimasti.

Adattamento per i segreti (D-02): **nessun valore va trascritto.** Il confronto tra il valore ricevuto dal container e quello del file segreti si fa dentro il comando, e nel file si scrive solo l'esito, per esempio `DATABASE_URL: uguale al file segreti` oppure `uguale=si|no`. Per la prova 1 conviene un valore fittizio dell'host riconoscibile (es. `CKA_FAKE_HOST_VALUE`) e verificare che *non* arrivi, senza mai stampare il valore vero. Per la prova 2 serve una variabile dell'host con nome assente dal file segreti e dal compose: si verifica che non compaia nell'ambiente del runner. Per la prova 3 si ripete la sequenza acquire, up, oneshot, ps --assert-only, release, con i soli exit code.

## Pattern condivisi

- **Nessun valore stampato:** già regola d'intestazione di `session.sh:25-26` e di bench.sh riga 384. Vale sia per lo script sia per il file di evidenza.
- **Errori ed exit code:** `err` / `die <code>` (`session.sh:43-44`): 2 per l'uso o la configurazione, 1 per un'asserzione fallita.
- **Git Bash:** `MSYS_NO_PATHCONV=1` e `hostpath` (`session.sh:31, 48-50`) restano invariati; `env -u` è disponibile in Git Bash (coreutils).
